## Observaciones nuevas (serie R4-xx, dentro de las 3 operaciones)

### R4-01 — Gramática de `timestamp` de baja sin cerrar (hija de R3-02). Severidad media-alta. BLOQUEA (cambia veredicto).

- Texto obedecido: R3-02 ("`timestamp` de baja ausente o no ISO-8601 UTC → `400 MALFORMED_DROP_TIMESTAMP`") + `contracts.md` §2-P4 ("`timestamp` ISO-8601 UTC … Informativo") + PRD §4.3 l.182 ("Timestamp ISO 8601", sin gramática) + ejemplo PRD l.222 (`2026-09-12T10:14:22.004Z`, milisegundos, no microsegundos). El `at` interno sí tiene gramática cerrada (6 micros + zona explícita, §1-P3); el `timestamp` de baja no fija dígitos fraccionales ni forma de zona (`Z` vs `+00:00`) ni si acepta milisegundos.
- Par: `POST …/subjects/CS-480/enrollments/STU-X/drop` con `timestamp: "2026-09-23T15:04:05Z"` (sin fracción) o `"…05.120000+00:00"`. Unidad A (hereda la gramática estricta del `at`: exige microsegundos + `Z`) → `400 MALFORMED_DROP_TIMESTAMP`. Unidad B (acepta cualquier ISO-8601 con zona UTC) → pasa sintaxis y sigue a 200/`ALREADY_REVOKED`. Divergencia observable 400-vs-200 dentro de `revokeCourseAccess`, ambas citando el mismo texto.
- No se propone aquí ninguna gramática; se registra como cierre incompleto de R3-02.
